# ИИ-агент первой линии технической поддержки 

## О проекте

Проект представляет собой прототип интеллектуального агента технической поддержки, предназначенного для анализа входящих обращений, поиска похожих инцидентов и подготовки рекомендаций для инженеров поддержки.

Основная идея — объединить обращения, поступающие по электронной почте и телефону, с локальной базой знаний, содержащей ранее зарегистрированные технические проблемы и решения.

В качестве целевой основной языковой модели проекта предусмотрена **Qwen3.8**.

## Основные возможности

### 1. Приём и обработка обращений

Предусмотрены два основных источника входящих обращений:

- Электронная почта Gmail;
- Аудиозаписи телефонных разговоров в формате MP3.

**Обработка электронной почты:**
- Получение писем через почтовый сервер;
- Извлечение текста обращения;
- Сохранение прикреплённых файлов;
- Анализ изображений во вложениях;
- Формирование единого тикета в формате Markdown.

**Обработка аудио:**
- Загрузка аудиозаписи;
- Распознавание речи с помощью Qwen3-ASR;
- Преобразование распознанного текста в структурированный тикет Markdown.

### 2. Анализ изображений

Для анализа изображений используется Qwen2.5-VL 3B, запускаемая через Ollama.

Модель позволяет получать текстовое описание изображений, прикреплённых к обращениям. Полученное описание может быть добавлено к основному содержимому тикета.

### 3. Подготовка базы знаний

В качестве базы знаний используются технические обращения из двух источников:

- **BZ (Bugzilla)** — зарегистрированные ошибки и проблемы;
- **RHEL** — обращения из базы технической поддержки Red Hat.

Карточки обращений хранятся в формате Markdown в каталоге `data/tickets/`.

Для дальнейшей обработки предусмотрен скрипт формирования CSV-таблиц с информацией о тикетах и найденных решениях.

### 4. Поиск похожих обращений (RAG)

Для поиска по локальной базе знаний реализованы два механизма:

**BM25**
- Поиск по ключевым словам;
- Подходит для поиска по точным идентификаторам, названиям компонентов и кодам ошибок.

**Семантический поиск**
- Использует multilingual-e5-small;
- Находит обращения по смысловому сходству, даже если формулировки отличаются;
- Использует локальный индекс эмбеддингов.

Результаты двух механизмов используются Hermes Agent при анализе нового обращения.

### 5. Hermes Agent

Hermes Agent выступает в роли основного оркестратора интеллектуальной обработки.

Его задачи:

1. Анализировать поступившее обращение;
2. Выделять компонент, симптомы, версии и диагностические данные;
3. Выполнять поиск по локальной базе знаний.
4. Читать найденные карточки целиком;
5. Сравнивать условия возникновения и наблюдаемые симптомы;
6. Определять отношение между обращениями;
7. Предлагать применимое решение либо запрашивать недостающую диагностику.

Агент использует следующие типы классификации:

| Тип | Значение |
|---|---|
| `same_problem` | Та же проблема |
| `similar_symptom` | Похожие симптомы, но одинаковая проблема не доказана |
| `different_problem` | Другая проблема |
| `uncertain` | Недостаточно данных для определения |

Итоговое решение и отправка ответа заказчику должны подтверждаться инженером.

## Установка и настройка

### Требования

- Windows с установленным WSL 2.
- AlmaLinux 10 в WSL 2.
- Python 3.12.
- Git.
- Настроенный Hermes Agent.
- Доступ к провайдеру языковой модели для текущего тестирования.
- Ollama для запуска Qwen2.5-VL.
- Локальные веса моделей, используемых для ASR и семантического поиска.

### 1. Подготовка окружения

Откройте Windows PowerShell и проверьте доступные дистрибутивы:

```powershell
wsl --list --verbose
```

Запустите AlmaLinux:

```powershell
wsl -d AlmaLinux
```

Внутри AlmaLinux выполните:

```bash
sudo dnf install -y git python3 python3-pip
```

### 2. Клонирование репозитория

```bash
git clone https://github.com/Vedmix/Test-Case.git
cd ~/Test-Case
```

### 3. Установка зависимостей RAG

```bash
python3 -m venv hermes-rag/.venv

hermes-rag/.venv/bin/python -m pip install -r hermes-rag/requirements.txt
```

Для остальных Python-модулей установите зависимости из корневого файла:

```bash
python3 -m venv .venv

source .venv/bin/activate

pip install -r requirements.txt
```

### 4. Подготовка локального индекса

Из корня репозитория выполните:

```bash
hermes-rag/.venv/bin/python hermes-rag/semantic_search.py index
```

После индексации должны появиться:

```text
hermes-rag/index/embeddings.npy
hermes-rag/index/metadata.json
```

### 5. Проверка поиска

Проверка BM25:

```bash
hermes-rag/.venv/bin/python hermes-rag/search.py 'BZ#1759941' --limit 5
```

Проверка семантического поиска:

```bash
HF_HUB_OFFLINE=1 hermes-rag/.venv/bin/python hermes-rag/semantic_search.py search \
'Directory Server: изменения схемы LDAP не реплицируются на второй сервер' --limit 5
```

### 6. Настройка Hermes Agent

Необходимо установить Hermes Agent и настроить провайдера языковой модели.

Для текущего прототипа используется Qwen3.8.

Скопируйте системный промпт в профиль Hermes:

```bash
hermes_home="${HERMES_HOME:-$HOME/.hermes}"

mkdir -p "$hermes_home"

cp promts/system-prompt.md "$hermes_home/SOUL.md"
```

Запустите агента из корня репозитория:

```bash
hermes
```

## Тестирование и оценка

Для проверки работы Hermes Agent разработан скрипт пакетного тестирования:

```bash
python3 tests/test_all_tickets.py --max-tickets 2
```

Запуск полной проверки:

```bash
python3 tests/test_all_tickets.py
```

Скрипт:
- последовательно передаёт тикеты Hermes Agent;
- выполняет поиск по локальной базе знаний;
- классифицирует найденные обращения;
- сохраняет промежуточные результаты;
- формирует пары для последующей оценки;
- строит предварительные группы по подтверждённым совпадениям `same_problem`.

Результаты сохраняются в каталоге `results/`:

| Файл | Содержание |
|---|---|
| `hermes_test_results.csv` | Результаты обработки каждого тикета |
| `hermes_test_pairs.csv` | Результаты сравнения пар тикетов |
| `hermes_test_raw.jsonl` | Исходные ответы Hermes и распознанные результаты |
