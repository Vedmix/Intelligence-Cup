# Устройства NVMe не восстанавливаются после сброса подсистемы

| Поле | Значение |
| --- | --- |
| Тикет | RHEL-137435 |
| Компонент | NVMe / PowerPC |
| Статус | Исправлено по данным Red Hat |
| Релиз с исправлением | RHEL 9.8 |

## Симптом

Устройства NVMe не восстанавливаются после сброса подсистемы.

## Условия и признаки

На PowerPC контроллер NVMe после сброса подсистемы остаётся в состоянии `resetting` и не возвращается в работу без перезагрузки.

## Причина

Дефект проявляется при `nvme subsystem-reset`. Во время штатного перехода контроллер тоже кратковременно недоступен.

## Диагностика и проверка исправления

На стенде с выделенным устройством повторите сброс на ядре с исправлением. Проверьте по журналу ядра и состоянию контроллера, что после `resetting` наступает `live` и возобновляется доступ к устройству. На рабочем узле для первичной диагностики используйте имеющиеся журналы и не инициируйте сброс.

## Решение
Используйте сборку компонента «NVMe / PowerPC» с исправлением из RHEL 9.8. Для другой ветки или канала обновлений сверяйте наличие исправления по номеру RHEL-137435.

## Данные из трекера

Описание исправления сверено с примечаниями к выпуску. Переписка для этой карточки не собрана.

## Другие формулировки симптома

- На PowerPC NVMe застревает в resetting после subsystem-reset.

## Диагностические данные

**Что есть в источнике.** По доступным материалам состав собранных при расследовании данных не установлен.

**Что запросить при похожем обращении.** Модель контроллера, ядро, журнал сброса и последовательность состояний. Также нужны версия RHEL, точная сборка затронутого компонента и время проявления сбоя.
