# В журнале появляется предупреждение об устаревшем ipset

| Поле | Значение |
| --- | --- |
| Тикет | BZ#2122678 |
| Компонент | firewalld |
| Статус | Исправлено по данным Red Hat |
| Релиз с исправлением | RHEL 9.2 |

## Симптомы

При работе `firewalld` в журнале ядра появляется предупреждение об устаревшем модуле `ipset`, хотя прямые правила с ipset не используются.

## Причина

Служба задействовала модуль ядра без необходимости.

## Решение

Обновите `firewalld`. После исправления модуль используется при явном применении ipset через `--direct`.

## Проверка

В тестовой системе без таких прямых правил проверьте журнал ядра через `journalctl -k -b` после обычного запуска службы. Нового предупреждения от запуска быть не должно.

## Диагностика на стенде

Проверьте `rpm -q firewalld`, `firewall-cmd --get-ipsets` и `firewall-cmd --direct --get-all-rules`. На стенде с backend nftables сравните два сценария: использование набора как источника зоны и использование набора в прямом правиле. Смотрите свежие записи ядра в каждом сценарии, начиная с чистой загрузки.

## Переписка в Bugzilla

Выборочный пересказ публичных комментариев.

- **30 августа 2022, описание.** Эрик Гарвер связал предупреждение с созданием нативного набора `ipset`. Для обычного правила зоны достаточно набора nftables. Нативный набор нужен для прямых правил.
- **8 сентября, комментарий № 2.** Гарвер перечислил изменения upstream, включая `cdd015475e83`, который откладывает создание нативного набора при использовании nftables, и тест этого поведения.
- **8 ноября, комментарий № 3.** Гарвер добавил ссылку на [запрос на слияние в CentOS Stream](https://gitlab.com/redhat/centos-stream/rpms/firewalld/-/merge_requests/11).
- **9 мая 2023, комментарий № 15.** Bugzilla закрыла тикет как `CLOSED ERRATA`. Исправленная сборка в карточке — `firewalld-1.2.1-1.el9`. [RHBA-2023:2546](https://access.redhat.com/errata/RHBA-2023:2546)

## Другие формулировки симптома

- При использовании обычного набора адресов firewalld ядро пишет, что модуль ipset устарел.

## Диагностические данные

**Что есть в источнике.** В описании Bugzilla приведены предупреждение ядра об устаревании `ipset` и пример использования набора как источника зоны. В комментариях перечислены изменения upstream и тест отложенного создания нативного набора.

**Что запросить при похожем обращении.** Backend firewalld, наборы адресов, список direct-правил, предупреждение из журнала ядра. Также нужны версия RHEL, точная сборка затронутого компонента и время проявления сбоя.
