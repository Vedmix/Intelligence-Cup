# system() не всегда восстанавливает маску сигналов

| Поле | Значение |
| --- | --- |
| Тикет | BZ#2177235 |
| Компонент | glibc |
| Статус | Исправлено по данным Red Hat |
| Релиз с исправлением | RHEL 9.3 |

## Симптом

system() не всегда восстанавливает маску сигналов.

## Условия и признаки

Многопоточная программа одновременно вызывает `system()` из разных потоков. После возврата в одном из них `SIGCHLD` остаётся заблокированным, хотя до вызова он был разрешён.

## Причина

Гонка нарушала восстановление маски сигналов текущего потока.

## Диагностика и проверка исправления

Зафиксируйте `rpm -q glibc`. В отдельном тесте сравните маски каждого потока через `pthread_sigmask()` до и после серии синхронных параллельных вызовов `system()`. Повторите на исправленной glibc. Маска каждого потока должна совпасть с его исходной маской.

## Решение
Используйте сборку компонента «glibc» с исправлением из RHEL 9.3. Для другой ветки или канала обновлений сверяйте наличие исправления по номеру BZ#2177235.

## Данные из трекера

Описание исправления сверено с примечаниями к выпуску. Переписка для этой карточки не собрана.

## Другие формулировки симптома

- После параллельного system() в потоке неожиданно остаётся заблокирован SIGCHLD.

## Диагностические данные

**Что есть в источнике.** По доступным материалам состав собранных при расследовании данных не установлен.

**Что запросить при похожем обращении.** Версия glibc, пример параллельного вызова и маски потоков до и после. Также нужны версия RHEL, точная сборка затронутого компонента и время проявления сбоя.
