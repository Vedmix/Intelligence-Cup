# После NetApp giveback зависает ввод-вывод при смене D_ID

| Поле | Значение |
| --- | --- |
| Тикет | BZ#2173947 |
| Компонент | lpfc |
| Статус | Исправлено по данным Red Hat |
| Релиз с исправлением | RHEL 9.3 |

## Симптом

После NetApp giveback зависает ввод-вывод при смене D_ID.

## Причина и условия

При обмене идентификаторами порта `D_ID` гонка оставляла драйвер `lpfc` в неконсистентном состоянии. Наличие альтернативных путей не гарантировало продолжение ввода-вывода.

## Решение

После обновления ядра повторите giveback только на стенде и сопоставьте ошибки ядра с доступностью SAN-тома и продолжением ввода-вывода.

## Данные из трекера

Описание исправления сверено с примечаниями к выпуску. Переписка для этой карточки не собрана.

## Другие формулировки симптома

- На SAN-узле операции LVM зависают после возврата путей NetApp.

## Диагностические данные

**Что есть в источнике.** По доступным материалам состав собранных при расследовании данных не установлен.

**Что запросить при похожем обращении.** Журнал lpfc и hung task, время giveback, D_ID и состояние multipath. Также нужны версия RHEL, точная сборка затронутого компонента и время проявления сбоя.
