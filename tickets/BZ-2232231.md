# Роль kdump не добавляет SSH-ключ при проблемах с authorized_keys

| Поле | Значение |
| --- | --- |
| Тикет | BZ#2232231 |
| Компонент | Системная роль kdump |
| Статус | Исправлено по данным Red Hat |
| Релиз с исправлением | RHEL 9.3 |

## Симптом

Роль kdump не добавляет SSH-ключ при проблемах с authorized_keys.

## Условия и признаки

При настройке удалённой выгрузки kdump роль может не добавить SSH-ключ для `kdump_ssh_user`, если каталог `.ssh` или файл `authorized_keys` недоступен пользователю либо ещё не подготовлен.

## Причина

Сбой затрагивает установку ключа ролью kdump для выбранной учётной записи.

## Диагностика и проверка исправления

Проверьте пользователя из плейбука, домашний каталог и права на `.ssh` и `authorized_keys`. После обновления роли повторите настройку на стенде и проверьте вход по ключу для выбранной учётной записи без запуска аварийного дампа.

## Решение
Используйте сборку системных ролей с исправлением из RHEL 9.3. Для другой ветки или канала обновлений сверяйте наличие исправления по номеру BZ#2232231.

## Данные из трекера

Описание исправления сверено с примечаниями к выпуску. Переписка для этой карточки не собрана.

## Другие формулировки симптома

- Роль kdump не устанавливает ключ для выбранной SSH-учётной записи.

## Диагностические данные

**Что есть в источнике.** По доступным материалам состав собранных при расследовании данных не установлен.

**Что запросить при похожем обращении.** kdump_ssh_user, права и владелец .ssh и authorized_keys, вывод задачи. Также нужны версия RHEL, точная сборка затронутого компонента и время проявления сбоя.
