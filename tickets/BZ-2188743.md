# tangd-keygen неправильно обрабатывает нестандартный umask

| Поле | Значение |
| --- | --- |
| Тикет | BZ#2188743 |
| Компонент | Tang |
| Статус | Исправлено по данным Red Hat |
| Релиз с исправлением | RHEL 9.3 |

## Симптом

tangd-keygen неправильно обрабатывает нестандартный umask.

## Условия и признаки

`tang-show-keys` сообщает `Internal Error 500` после генерации ключей на сервере с ограничительным `umask`.

## Причина

`tangd-keygen` оставлял режим доступа, заданный `umask`. Процесс Tang мог не иметь доступа на чтение.

## Диагностика и проверка исправления

Проверьте режимы файлов ключей и права учётной записи службы. На тестовом сервере после обновления Tang сгенерируйте ключи при том же `umask` и повторите `tang-show-keys`. Команда должна отобразить ключи. При диагностике фиксируйте права и владельцев файлов, содержимое ключей для этого не требуется.

## Решение
Используйте сборку компонента «Tang» с исправлением из RHEL 9.3. Для другой ветки или канала обновлений сверяйте наличие исправления по номеру BZ#2188743.

## Данные из трекера

Описание исправления сверено с примечаниями к выпуску. Переписка для этой карточки не собрана.

## Другие формулировки симптома

- tang-show-keys возвращает Internal Error 500 после генерации ключей при строгом umask.

**Что есть в источнике.** По доступным материалам состав собранных при расследовании данных не установлен.

**Что запросить при похожем обращении.** Режимы и владельцы файлов ключей, umask и журнал Tang. Также нужны версия RHEL, точная сборка затронутого компонента и время проявления сбоя.
