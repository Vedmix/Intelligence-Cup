# Восстановление ReaR зависает при записи в журнал

| Поле | Значение |
| --- | --- |
| Тикет | BZ#2172912 |
| Компонент | ReaR / systemd / rsyslog |
| Статус | Исправлено по данным Red Hat |
| Релиз с исправлением | RHEL 9.3 |

## Симптомы

В среде восстановления ReaR процессы, которым требуется журналирование, зависают.

## Причина

При загрузке среды восстановления не запускался сокет, необходимый для активации `rsyslog`.

## Решение

Обновите ReaR и создайте новый загрузочный образ. Исправленные юниты запускают сокет при загрузке среды восстановления.

## Проверка

В тестовом восстановлении убедитесь, что операции завершаются, а в `/var/log/messages` среды восстановления появляются записи.

## Диагностика на стенде

Сценарий особенно заметен при восстановлении системы с большим количеством файловых систем. Без работающего `rsyslog` сообщения накапливались в сокете `/dev/log`, после чего восстановление останавливалось. Для проверки загрузитесь с образа, созданного обновлённым ReaR, и сопоставьте прогресс восстановления с появлением новых записей в журнале среды восстановления.

## Переписка в Bugzilla

Комментарии Bugzilla не удалось прочитать. Описание причины и решения взято из примечаний Red Hat к выпуску.

## Другие формулировки симптома

- ReaR останавливается посреди восстановления, когда сообщения не принимает rsyslog.

## Диагностические данные

**Что есть в источнике.** По доступным материалам состав собранных при расследовании данных не установлен.

**Что запросить при похожем обращении.** Журнал rescue-среды, состояние сокета /dev/log, количество файловых систем. Также нужны версия RHEL, точная сборка затронутого компонента и время проявления сбоя.
