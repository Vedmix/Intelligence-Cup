# Показания df и du расходятся после удаления файла

| Поле | Значение |
| --- | --- |
| Тикет | RHEL-129403 |
| Компонент | GFS2 |
| Статус | Исправлено по данным Red Hat |
| Релиз с исправлением | RHEL 9.8 |

## Симптом

Показания df и du расходятся после удаления файла.

## Условия и признаки

После массового удаления файлов в GFS2 `df` по-прежнему сообщает о высоком использовании, а `du` видит заметно меньший объём данных.

## Причина

Учёт свободного места мог не обновиться после удаления. Расхождение `df` и `du` само по себе не идентифицирует этот дефект.

## Диагностика и проверка исправления

Зафиксируйте тип файловой системы через `findmnt -T <путь>` и проверьте, не удерживают ли удалённые файлы открытые дескрипторы. На тестовом GFS2 с исправлением сравните `df -B1` и `du -sx -B1` до и после массового удаления. Доступное место должно увеличиться после освобождения файлов.

## Решение
Используйте сборку компонента «GFS2» с исправлением из RHEL 9.8. Для другой ветки или канала обновлений сверяйте наличие исправления по номеру RHEL-129403.

## Данные из трекера

Описание исправления сверено с примечаниями к выпуску. Переписка для этой карточки не собрана.

## Другие формулировки симптома

- После очистки GFS2 df показывает занятое место, которого уже не видно в du.

## Диагностические данные

**Что есть в источнике.** По доступным материалам состав собранных при расследовании данных не установлен.

**Что запросить при похожем обращении.** findmnt, df и du до и после удаления и сведения об открытых дескрипторах. Также нужны версия RHEL, точная сборка затронутого компонента и время проявления сбоя.
