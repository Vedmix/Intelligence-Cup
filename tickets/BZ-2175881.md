# pcs config checkpoint diff пропускает изменения конфигурации

| Поле | Значение |
| --- | --- |
| Тикет | BZ#2175881 |
| Компонент | pcs / Pacemaker |
| Статус | Исправлено по данным Red Hat |
| Релиз с исправлением | RHEL 9.3 |

## Симптомы

При сравнении двух контрольных точек кластера команда `pcs config checkpoint diff` может не показать изменения ресурсов, устройств STONITH или ограничений.

## Причина

При чтении второго CIB использовалось содержимое первого из кэша.

## Решение

Обновите `pcs`. После исправления сравнение загружает данные каждой контрольной точки отдельно.

## Проверка

Сравните две тестовые контрольные точки с известным изменением в одном из затронутых разделов. Команда должна показать это изменение.

## Диагностика на стенде

В тестовом кластере выберите контрольную точку, существовавшую до добавления ресурса. Подставьте её номер вместо `1` в `pcs config checkpoint diff 1 live`, затем поменяйте стороны сравнения командой `pcs config checkpoint diff live 1`. Изменение должно появиться в разделе ресурсов с противоположными знаками. Зафиксируйте версию через `rpm -q pcs`.

## Переписка в Bugzilla

Выборочный пересказ публичных комментариев.

- **6 марта 2023, описание.** Мирослав Лисик воспроизвёл сбой на `pcs-0.11.4-6.el9`. При сравнении контрольной точки с текущей конфигурацией вывод содержал изменения свойств кластера, но пропускал ресурсы, ограничения и другие разделы.
- **20 марта, комментарий № 6.** Лисик приложил сценарий проверки с добавлением ресурсов, fencing, ограничений и тегов. Сравнение запускалось в обоих направлениях. [Исправление в ClusterLabs/pcs](https://github.com/ClusterLabs/pcs/commit/76b2f524f64e66d99b8a9fef68c70532361f8a65)
- **26 мая, комментарий № 11.** Михал Поспишил опубликовал результаты проверки `pcs-0.11.5-1.el9.x86_64`. В выводе снова появились изменения ресурсов и устройств STONITH. Позднее QA отметила `pcs-0.11.5-2.el9.x86_64` как `VERIFIED`.
- **7 ноября, комментарий № 33.** Bugzilla закрыла тикет как `CLOSED ERRATA` после публикации обновления. [RHSA-2023:6316](https://access.redhat.com/errata/RHSA-2023:6316)

## Другие формулировки симптома

- При сравнении CIB видны свойства кластера, но теряются изменения ресурсов и STONITH.

## Диагностические данные

**Что есть в источнике.** В Bugzilla приведены исходная сборка `pcs-0.11.4-6.el9`, сценарий с ресурсами, fencing и ограничениями, вывод сравнения контрольных точек, сборки проверки и результат регрессионного теста.

**Что запросить при похожем обращении.** Номера контрольных точек, версия pcs и вывод diff в обе стороны. Также нужны версия RHEL, точная сборка затронутого компонента и время проявления сбоя.
