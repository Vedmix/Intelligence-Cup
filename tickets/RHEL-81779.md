# При обновлении неверно сравниваются epoch, version и release

| Поле | Значение |
| --- | --- |
| Тикет | RHEL-81779 |
| Компонент | DNF |
| Статус | Исправлено по данным Red Hat |
| Релиз с исправлением | RHEL 9.8 |

## Симптом

При обновлении неверно сравниваются epoch, version и release.

## Условия и признаки

Два последовательных обновления меняют только поле RPM `Release`, а DNF классифицирует результат как понижение версии.

## Причина

DNF некорректно сравнивал совокупность `Epoch`, `Version` и `Release` (EVR).

## Диагностика и проверка исправления

На стенде подготовьте последовательность сборок с одинаковыми `Epoch` и `Version` и возрастающим `Release`. Зафиксируйте EVR всех сборок. После обновления DNF повторите последовательность и проверьте классификацию транзакции.

## Решение
Используйте сборку компонента «DNF» с исправлением из RHEL 9.8. Для другой ветки или канала обновлений сверяйте наличие исправления по номеру RHEL-81779.

## Данные из трекера

Описание исправления сверено с примечаниями к выпуску. Переписка для этой карточки не собрана.

## Другие формулировки симптома

- Рост RPM Release при неизменных Epoch и Version ошибочно считается downgrade.

## Диагностические данные

**Что есть в источнике.** По доступным материалам состав собранных при расследовании данных не установлен.

**Что запросить при похожем обращении.** EVR всех сборок, порядок транзакций и вывод истории DNF. Также нужны версия RHEL, точная сборка затронутого компонента и время проявления сбоя.
